# Завдання: вирівняти відступи в CSS (apps/web)

## Проблема

Приблизно 80% правок вигляду — це нерівні відступи. Причина системна:

- У `apps/web/src/styles/tokens.css` є токени кольорів, шрифтів, радіусів і тіней, але **немає жодного токена відступів**.
- По `apps/web/src/**/*.css` розкидано ~1739 оголошень `margin` / `padding` / `gap` з голими px і **0** через `var()`.
- Використовується 64 різні значення, багато непарних: 8px ×265, 10px ×204, 12px ×184, 7px ×161, 6px ×152, 9px ×151, 5px ×149, 4px ×125, 14px ×117, 11px ×62, 15px ×41, 13px ×37, 17px ×28.
  Через це сусідні блоки мають 7 / 8 / 9 / 10px, і кожна точкова правка додає ще одне значення «на око».
- Найбільше відступів у таких файлах: `styles/pages.css` (577, файл на 6253 рядки, 119 повторних селекторів), `styles/components.css` (304), `features/messages/messages.css` (166), `features/feed-showcase/feed-showcase.css` (156), `features/feed/feed-card-design.css` (109), `layout/right-communication-panel.css` (94), `features/drive/drive.css` (79), `styles/layout.css` (73).
- 17 класів визначені одночасно в `components.css` і `layout.css`, тож правка в одному з них може бути перекрита:
  `.page-header`, `.list-toolbar`, `.filter-panel` (+ дочірні), `.task-list-table td:first-child`, `.task-presets button`, `.entity-form`, `.span-2`, `.overlay-layer--palette`, `.detail-grid`, `.task-subtasks > header`, `.task-subtask-list > a`, `.task-subtask-form`.
  `.page-header` є ще й у `pages.css`.

## План

1. **Шкала відступів у `tokens.css`** (сітка на 4px):
   `--space-0_5: 2px; --space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px; --space-5: 20px; --space-6: 24px; --space-8: 32px; --space-10: 40px; --space-12: 48px;`
   Плюс кілька смислових токенів поверх шкали: внутрішній відступ картки, відступ сторінки, проміжок між секціями, проміжок між іконкою й текстом, відступ поля форми. Назви — на твій розсуд, але коротко й послідовно.
2. **Переводити розділ за розділом**, а не весь проєкт одразу:
   каркас (layout, page-header, фільтри, форми) → задачі → стрічка → повідомлення та права панель → Drive → решта.
   Непарні значення округлювати до найближчого кроку шкали. Нульові значення й px для бордерів/ліній (1px) не чіпати.
3. **У розділі, який правиш, прибирати дублікати селекторів.** Правило має жити в одному місці.
4. **Після кожного розділу**: запустити `npm run dev`, переглянути сторінки розділу у браузері (десктоп і вузький екран), порівняти з тим, що було до правок. Перевірити `npm run lint --workspace @lankadws/web`.
5. Наприкінці кожного розділу коротко звітувати: що змінено, які сторінки переглянуто, що виглядає інакше.

## Обмеження

- Тільки CSS і вигляд. Не змінювати логіку, контракти, API, Prisma.
- Дотримуватись `AGENTS.md` і `CLAUDE.md` (не сканувати `node_modules`, `output/`, `.playwright-cli/` тощо).
- Великий робочий стан у git не закомічений. Нічого не відкатувати й не комітити без запиту.
