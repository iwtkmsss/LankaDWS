# Перевірка завантажених файлів

## Linux і Docker

Застосунок використовує ClamAV (`clamd`) як окремий сервіс. Файли передаються
потоком INSTREAM через приватну мережу Docker; спільний файловий volume з API
сканеру не потрібний. Defender і сторонні публічні сервіси не використовуються.

```sh
docker compose -f deploy/clamav/compose.yaml up -d --wait
docker compose -f deploy/clamav/compose.yaml ps
docker compose -f deploy/clamav/compose.yaml logs --tail=100 clamav
```

Контейнер запускає `clamd` і FreshClam для оновлення сигнатур; база зберігається
у named volume. Виділіть 4 GiB RAM додатково до ресурсів API/БД. Перше
завантаження баз і запуск рушія можуть тривати кілька хвилин. Образ за
замовчуванням — офіційний `clamav/clamav:stable`; перед production зафіксуйте
перевірений тег або digest через `CLAMAV_IMAGE`, оновлюйте його планово.

Для API, що також працює в Docker, приєднайте його до зовнішньої мережі
`lankadws-scanner` і встановіть:

```dotenv
MALWARE_SCANNER=clamav
CLAMAV_HOST=clamav
CLAMAV_PORT=3310
SCANNER_TIMEOUT_MS=30000
JOB_LEASE_SECONDS=60
```

Приклад фрагмента compose для наявного API (додайте мережу до інших його мереж):

```yaml
services:
  api:
    networks:
      - scanner
networks:
  scanner:
    external: true
    name: lankadws-scanner
```

Якщо API запускається без Docker на тому самому Linux-хості, використовуйте
`CLAMAV_HOST=127.0.0.1`. Порт 3310 публікується лише на loopback. Протокол
clamd не має автентифікації чи шифрування: не відкривайте його в інтернет.
Сканеру потрібен вихід у мережу для оновлення баз. Не вимикайте FreshClam.

Перезапустіть API після зміни його environment. `DISABLE_JOB_WORKER=true`
не повинен бути встановлений: перевірки виконуються фоновим worker API.

Перевірка реального рушія з environment і мережі API:

```sh
npx tsx apps/api/scripts/check-file-scanner.ts
```

Очікується `ClamAV: clean sample accepted; EICAR blocked.` Скрипт створює
звичайний текст і нешкідливий стандартний тест EICAR, передає обидва сканеру
та видаляє свої тимчасові файли. Він не завантажує справжнє шкідливе ПЗ і не
змінює БД. Окремо перевірте upload/download через API після розгортання.

## Шлях файла

1. API перевіряє ненульовий розмір, ліміт і фактичний тип вмісту. Файл
   записується в карантин, у БД — `QUARANTINED`; ставиться durable `file.scan` job.
2. Worker виставляє `SCANNING`, перевіряє розмір і SHA-256, передає байти ClamAV.
3. Лише точна відповідь `stream: OK` дозволяє переведення в `CLEAN`. Перед
   перенесенням у доступне сховище знову перевіряються розмір і SHA-256.
4. `FOUND` дає `INFECTED`. Сигнали про зашифрований вміст або перевищені ліміти
   дають `UNSUPPORTED`: файл не вважається перевіреним. В обох випадках файл
   залишається в карантині, завантаження, preview і ZIP недоступні.
5. Відсутній сканер, timeout, помилка, обірвана/неочікувана відповідь або
   змінений файл не дозволяють `CLEAN`. Job повторюється з backoff; після
   вичерпання спроб файл отримує `FAILED`, а не нескінченне «Перевіряється».
   Після відновлення сервісу failed `file.scan` jobs можна повторити через
   наявне адміністрування jobs; вручну ставити `CLEAN` не потрібно.

У завданні статус окремого вкладення й готовність ZIP використовують спільний
кеш перевірок з опитуванням раз на 2 секунди, доки стан не стане кінцевим.
Після `CLEAN` напис змінюється на розмір файла, ZIP стає доступним без reload.
При `FAILED` показується «Не вдалося перевірити файл»; заблокований ZIP не
обіцяє завершення перевірки.

## Захист і межі

ClamAV шукає відомі шкідливі сигнатури та підозрілі конструкції, зокрема у
підтримуваних офісних документах, PDF і вкладених архівах. Це зменшує ризик
поширення заражених вкладень між користувачами. Налаштовано блокування
зашифрованих архівів/документів, які рушій не може прочитати, і перевищень
лімітів розпакування. Ліміт upload/stream/file — 100 MiB, загального
розпакованого вмісту — 200 MiB, вкладеності — 16, файлів в архіві — 10 000,
часу сканування — 25 секунд; timeout клієнта — 30 секунд (і нижче lease job).
Підвищуючи upload-ліміт, узгоджуйте його з налаштуваннями сканера.

Антивірус не гарантує відсутності нових/невідомих загроз, не є sandbox і не
перевіряє правдивість документа, права на його передачу або всі небезпечні
посилання. Помилкові спрацювання можливі. Оновлення сигнатур і самого рушія
залишаються обов'язковими; захист кінцевих пристроїв також потрібний.

Раніше позначені `CLEAN` файли автоматично не перескановуються: попередній
тестовий вердикт не є доказом антивірусної перевірки. Масовий повторний scan
наявних файлів — окрема операція з планом доступності та backup.

`development-clean` збережений лише для ізольованих тестових сценаріїв;
в production він заборонений. При розгортанні явно задайте `MALWARE_SCANNER=clamav`
і перевірте environment процесу: зміна `.env.example` не змінює наявний `.env`.

Джерела: [ClamAV INSTREAM](https://docs.clamav.net/manual/Usage/ClamdProtocol.html),
[офіційний Docker-образ і ресурси](https://docs.clamav.net/manual/Installing/Docker.html),
[параметри clamd](https://github.com/Cisco-Talos/clamav/blob/main/etc/clamd.conf.sample).
